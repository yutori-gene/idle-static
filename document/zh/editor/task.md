
# 任务
满足条件即达成的使命
- 满足设置的条件后即达成，画面上部会显示消息。
- 会显示在运行器的使命列表和类别的任务列表中。
- 没有设置条件的任务不会达成。
- 一旦达成，之后即使不再满足条件也保持达成状态，奖励也随时可以领取。
- 奖励不会自动发放。玩家打开任务并按下获得栏时才领取。
- 在领取奖励之前，列表的栏上会附上丝带，表示尚未领取。
- 没有设置奖励的任务不会出现获得栏，达成的时点即算完成。
- 可持有的物品种类达到上限时无法领取奖励。请整理之后再重新领取。
- 通过获得可以改变类别的等级、动作的执行次数、物品的持有数。
- 首次启动时或游戏结束时等，想在条件以外的时机发动的内容，用固定事件（unique）来设置。
- [_unique_](zh/editor/unique)

## 类别
任务所属类别的ID
- 指定让这个任务所属的类别的ID。
- 设置后，运行器的类别画面中会添加任务列表，在使命列表中也会按类别汇总显示。
- 留空时不属于任何类别，会汇总显示在使命列表的开头。
- 任务自身没有设置颜色时，会继承类别的颜色。
- [_category_](zh/editor/category)
___

## 时机
任务发动的时机（固定为`tasked`）
- 任务固定为`tasked`（满足设置的条件时），无法编辑。
- 奖励只能领取一次，领取后此后就保持达成状态不再变化。
- 想在其他固定时机发动的内容，用固定事件（unique）来设置。
- [_unique_](zh/editor/unique)
___

## 初始显示状态
任务图标的初始显示状态（达成由条件决定，此设置不会使其达成）
- 任务的达成条件由requirements决定，此项目只影响列表图标的外观。
- secreted：在满足全部requirements之前完全不显示在任务列表中（达成本身仍由条件触发）。
- hidden・hinted：图标上会加上斜线，显示为未开放。
- released：斜线消失，显示为已开放。
- 一旦达成的任务不会从列表中消失，之后即使不再满足条件也仍显示为达成。

## 分组汇总
将条件的id作为分组ID处理，用所属要素的合计值来判定
- 启用后，条件（requirements）中设置的id会作为世界直属分组的ID来处理。
- 类型为类别的条件，用属于该分组的全部类别的等级合计来判定。
- 类型为动作的条件，用属于该分组的全部动作的执行次数合计来判定。
- 类型为物品的条件，用属于该分组的全部物品的持有数合计来判定。
- 未开放（released以外）的要素不计入合计。
- 物品的消耗概率（chance）和装备条件（equipment）会被忽略，也不会消耗持有数。仅用于判定。
- 停用时与以往相同，条件的id会作为单个类别・动作・物品的ID来处理。
- [_group_](zh/editor/group)

## 任务分组
任务的显示分组分类
- 请套用世界直属的分组中定义的其中之一。
- 在类别的任务列表中，会按分组加上标题分开显示。没有设置分组的任务也会成为一个整体，标题使用预设的「任务」。
- 在使命列表中不按标题分开，只有排列顺序会按分组汇集。
- 各整体的排列顺序，由该分组的任务最先出现的位置决定。
- [_group_](zh/editor/group)
